## Effective amendments over inherited prose

Revision 9 adds `TermCard.arabic`, typed `StoredGlossaryTerm`/`Draft.glossary`, nullable `Step.secondary_label`/`Category.art_key`, and explicit `POrderSteps.presentation`. Use the amended canonical models and the API requirements. Canonical Arabic preserves authored Unicode/diacritics independently of locale/definition level.

Retained revision 8 repairs include chronological/unique history, truthful rejection tests, typed payload/event custom export, linked contextual answer/evaluation/private-key checks, corrected flashcard hard mastery (0.40 → 0.49), stable translated exercise identity/type, coherent curriculum/assessment pools, stronger scene grammar/geometry/assets/descendant-state checks and honest simulation/production capability registries. The original human-readable handoffs did not restate every code repair; these rules remain part of the effective baseline through the canonical code and independent review.

**Replay-first:** a framework must not eagerly validate the complete `AnswerSubmit` body before replay lookup (normative order: API §6.5). Authenticate and obtain parseable identity, read any recorded response, then validate a fresh attempt and transact. The contextual helper is for fresh attempts and cannot prove authoritative timers, ownership, concurrency or side-effect durability.

**Projection:** current reference term/cards and bank fixes are source-backed. Legacy backfill supplies explicit null/plain defaults only; it cannot invent Arabic or prayer decoration. Version-aware migrations must retain already pinned content/session semantics.

**Scene release:** static validation alone cannot prove composed transforms, visible targets, transition determinism or app/preview equality. The semantics are now defined ([SCENE_RENDERER_SEMANTICS.md](../07_ANIMATION/SCENE_RENDERER_SEMANTICS.md)); capabilities still need the release evidence in its §8 before they become production-eligible. A wire-meaning change requires scene/capability versioning.

## Assumptions needing review

The inherited single-Uvicorn-worker challenge approach is a hackathon assumption. AD-23 specifies the durable replacement; a constrained pilot remains possible only with explicit approval (O-04). Provider/model names, Python/native dependencies, CPU ASR capacity, source credentials/licenses, asset hosting, retention periods and metrics targets are proposals requiring verification. Preserve the contract when changing them. No live provider availability or benchmark result is asserted here.

The [reply7 independent assessment](../11_HISTORY/reply7/INDEPENDENT_ASSESSMENT.md) explains these production caveats. The [implementation plan](../08_IMPLEMENTATION/SHARED_IMPLEMENTATION_PLAN.md) carries them into work and acceptance gates.
