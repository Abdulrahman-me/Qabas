1. Legacy/pinned version migration is tested.
2. Play all 14 reference steps through mock and live typed repositories/controllers in ar/en × both tracks. Preserve 54 canonical cards, all 12 banks and private/public separation.
3. Test real Postgres race/replay/finish/outbox/crash behavior and feedback redaction. Compare private six-decimal calculations with rounded public snapshots; recorded identities with malformed changed bodies still replay after auth.
4. Publish a new non-Salah asset-bearing declarative scene using released capabilities. The app and normative preview produce matching controlled state/time frames/transitions, reduced-motion still and state-aligned fallback; test actual raster/SVG bytes, missing/corrupt downloads, hashes/MIME/dimensions, unsupported capability, anchors, pinned resume and measured devices.
5. Complete source/religious approval, licensed clip/timings, registries, bound recitation checks, published gold/evaluation/finish fixtures. Synthetic tones and model-card statements do not close recognition or audio gates.
6. Execute broader product flows: many units/pools/reviews/adaptation, eight Raqeeb classes and all inputs, community/challenge recovery/timers/ties/bot/async, onboarding/privacy/quests/achievements/guides/glossary, factory two gates/regeneration/immutable publication and real metrics.
9. **Curriculum and learning design (curriculum amendment):** both tracks over one canonical curriculum (Unit 0 Explorer-only), Roadmap and Discover opening the identical session for the same lesson, prerequisite-based access with Soft Lock (no position-based unlocking, no lesson skip), completion shared across surfaces and track changes, onboarding without any religion question and with Goal Anchor bridges, factory plans with arcs/reasoning tools/budgets, sentence roles and claim basis, Arabic-to-English localization parity, and pedagogical QA that blocks belief grading, circular reasoning and meaning drift.
7. Build targeted mobile/web platforms; resolve retracted/native dependencies; test RTL/text size/font fallback/accessibility, outages/retention/backups, queue/API/realtime/device performance and repeatable deployment.
8. **Security, privacy and recovery (rev 10):** token revocation within 30 s and the non-looping client `401` path; tokens absent from URLs/logs; WebSocket tickets single-use, 60 s, caller-bound; `Idempotency-Key` replay and conflict; finish/abandon/async replay; `DELETE /me` purge completeness (including object storage and memory rows) and re-purge after restore; private attachments not reachable without a valid signed URL; rate limits return `429` with `retry_after_ms`; release bundles contain no private/mock data; challenge coordinator takeover (kill the owner mid-question: same deadline, no lost or duplicated points or XP); ASR back-pressure returns `503` while the API stays responsive.

Production reward/mastery behavior follows backend rules rather than prototype simulation. Preserve the agreed completion presentation/Remembering placeholder until an explicitly approved behavior change is recorded. Verify spelling/transliteration on devices; do not treat matching fallback boxes as typography approval.

## 18. Contract compliance and definition of done

### 18.1 Contract tests
- **Contract suites in CI** (both repos, from the vendored [revision 10](../03_API/contract_revision10/README.md) folder): `tools/validate.py` validates every JSON example in [API requirements](../03_API/API_REQUIREMENTS.md) through an explicit example → model map, every fixture in `fixtures/MANIFEST.json` with its model, semantic cross-object checks (mock assets, scenes/anchors/bindings, finish workflow, challenge scoring, recovery) and the negative suite; `tools/regression.py` (595) and `tools/rev10_checks.py` (279) must pass. Keys starting with `_mock` are stripped. Response models must stay equal to the contract models (a test diffs the served OpenAPI component schemas against `contract/qabas_contract.schema.json`).
- `test_registry_parity.py`: `content/visual_registry.yaml` equals contract §5.5c (keys, versions, params) and §5.5d (**per-use** proportions).
- `test_salah_reference.py`: for each of the 4 language × track combinations, `POST /sessions {kind: lesson, lesson_id: <reference lesson>}` (fixture ID `les_u1_l3`; production slot 3.2) returns a session **equal to the generated fixture** `session_salah_{lang}_{track}.json` (after normalizing ids, timestamps, and media hosts): same 14 steps, copy, terms (14 Arabic / 13 English), canonical Arabic displays, story label/provenance tags, glosses, visual keys/params, highlight sequences, hotspot coordinates/labels, evidence, and segment. Assert all 12 Dart-captured banks, ordering secondary labels and explicit bucket/header decorations, with unchanged private keys and gradeable interactions. `GET /lessons/<reference lesson>` equals the session's content after the documented **reader projection** (exercise blocks removed); a Gate 2-style preview equals the session items; resuming returns the identical snapshot. These are runtime acceptance requirements; the supplied projection/widget tests close only their stated isolated scope.
- `test_version_pinning.py`: publish a new lesson version (changed answer key, feedback, misconception mapping, and scene version) while a session is active; the active session's snapshot, assets, and grading stay on the served `exercise_versions`/`scene_versions`; a new session gets the new versions.
- `test_recitation_range.py`: a check of words 1–7 cannot be used to answer an exercise serving words 14–20 of the same ayah (409); matching range succeeds.
- `test_history_redaction.py`: for `immediate`, `end`, and `none` sessions — answer submission, duplicate submission, `GET`/resume, reconnect, and post-finish access return only what the mode allows (`result: hidden`, `evaluation: null` where required); grading and adaptation still use the private result.
- `test_recovery.py`: the backend's history feeds `tools/recovery.py` to the same outcomes as the contract fixtures: after an early **correct** retry, after an early **incorrect** retry (not requeued — once each), after an interrupted/unrecorded retry (still queued), mid-lesson, and with a defensive gap (resumes before the earliest unanswered exercise; nothing skipped or re-submitted).
- `test_attempt_identity.py`: (a) a repeated original and a repeated retry — with the same **and** with a different `answer` body — return the stored response, change nothing, and record nothing (incl. after an incorrect retry: no new grading); (b) the attempt table never holds two rows for one identity; (c) a retry whose identity is unrecorded is rejected with `409 retry_not_allowed` when the first attempt is missing, correct, neutral, or hidden-mode, or the type is recitation/flashcard, or the session isn't a lesson; (d) an out-of-order first attempt → `409 out_of_order`.
- `test_mastery.py`: evaluation snapshots and `mastery_summary` match §7.1 for the contract workflow (incl. retry and recitation), half-up rounding at 0.545 and 0.225.
- `test_finish_workflow.py`: the contract's §6.5 session + `fixtures/workflows/ses_91ab.json` history produce exactly the §6.5 finish example (1/2, understanding 1/2, no perfect, XP 15); skipped eligible items lower the denominator.
- `test_challenge_scoring.py`: group half-up boundary (500 ms → 103), duel floor, ties with two winners, reveal values.
- `test_scene_hotspots.py`: a pin moved off its anchor (same proportion), a state rule moving an anchored layer, a fallback rendered at another state, unknown/out-of-range bindings — all rejected at import/publish.
- `test_scoring.py`: recitation never enters accuracy/layers; `remember` counts in accuracy only; `counts` and `source_count` match the items; content > 3 sources rejected.
- `test_scenes.py`: scene validator rejects unreleased capabilities, out-of-range states, limit violations, missing fallback, and wrong fallback proportion; publishing makes the version immutable; sessions keep their served scene version.
- `test_assessment_supply.py`: pools below 6/9 block unit publication; sessions never repeat items; `nothing_to_review` when no flashcard exists.
- `test_null_correct.py`: `correct: null` answers are excluded from score, accuracy, layers, `lesson_perfect`, mastery, FSRS, misconceptions, quests.
- `test_curriculum.py`: on the test curriculum, journey states, prerequisite-based access and Soft Lock (`prerequisites`, `start_with`), `409 prerequisite_unmet`, `404` for a lesson outside the track, standalone/Discover listing, unit placement skipping and its satisfied prerequisites, next steps (pretest not recommended once a unit lesson is completed), review selection across units, and track/language switching (Explorer → New Muslim keeps completions, removes the Explorer-only unit) behave per §6–§7 without any id special cases.
- `test_discover_identity.py`: a lesson started from Discover and from the Roadmap yields byte-identical session content (version, variant, items, exercises, completion); finishing it once marks it completed on both surfaces; the request carries no surface field.
- `test_onboarding_privacy.py`: no endpoint accepts or returns a religion/worldview field; `goal_anchor` changes neither `start_unit_id` nor `next_step` nor the journey; unknown keys → `400`.
- `test_factory_pedagogy.py`: plan validators (one outcome with a central question, supporting understandings and a depth profile, standalone without prerequisites, justified tools, 2–6 exercise budget, arc with an interactive step); writer output covers every arc step in order; non-assertive roles carry no claims and disguised assertions are blocked; reasoning claims supported by scripture are rejected; English variants keep IDs, roles, claim links, keys and sources (code) and meaning (QA); belief-grading items block publication; pedagogical warnings appear for long or exposition-heavy lessons; Gate 2 rejects an unpaired Arabic edit. Composition: a second run for an occupied slot revises that lesson instead of creating a sibling; a story block outside a story/scenario step, a second summary or a teaching scenario with a claim or quote is blocked; duplicate hooks, summaries and near-duplicate exercises are reported; a concept lesson containing a scenario and practice is accepted and measured as one lesson; an unsound reasoning example in a reasoning lesson blocks publication. Depth: a 9-minute foundational lesson draws no duration warning; a lesson estimated beyond about 12 minutes draws a review warning, never an automatic split; adding minutes does not add graded exercises (a quiz-heavy lesson is warned); model QA reports a definition-only foundational lesson, a lesson narrower than its central question, missing supporting understandings, and lessons padded to a duration.
- `test_types.py`: every exercise type and presentation has evaluator tests for its applicable cases (correct, incorrect, misconception, invalid, timeout, retry, skipped/unavailable, `none`/`end` modes with no leakage).
- Evaluator tests for `categorize` `day_arc`: correct, swapped pair, duplicate item, missing item, unknown id, capacity overflow, `null` timeout; and that no learner payload contains answer keys or item phases.
- `map_place` tests: image and built-in visuals, `unavailable` handling.
- Error envelope: every non-2xx uses `{error: {code, message, details}}` with codes from contract §3.4.
- Multipart field names and limits exactly as in the contract.
- WebSocket: a test client plays a full bot duel and asserts the event order in contract §8.4; a **four-player group** test (three scripted friend clients) covers individual `opponent_answered` events with `user_id`, a timeout, one disconnect/reconnect restored from `live`, a rank-1 tie with two winners, group scoring/reveal values, and finish — matching `fixtures/challenges/group_ws_script.json`.
- `GET /openapi.json` is exported to `docs/openapi.json` for the frontend's contract check.
- **Rev 10 runtime tests (deliverables):** `test_auth_sessions.py` (revocation, expiry, deletion, no token in logs); `test_idempotency_keys.py` (same body replay, different body `409`, concurrent duplicates); `test_finish_replay.py` (timeout retry, changed `duration_ms`, missing first attempts `409 out_of_order`); `test_ws_tickets.py` (expired/reused/foreign ticket rejected at upgrade); `test_coordinator_takeover.py` (owner killed during question/reveal/lobby; fenced stale owner cannot write); `test_async_duel_idempotency.py`; `test_review_digest.py` (stale digest, concurrent decisions, edits re-validated, gold import cannot publish without approval); `test_account_deletion.py`; `test_rate_limits.py`; `test_raqeeb_memory_guard.py` (attachments/follow-ups never reuse; source digest change invalidates); `test_untrusted_input.py` (embedded instructions ignored); `test_asr_backpressure.py`.
- **Scene renderer tests (Flutter, P1):** mulberry32 test vectors; property precedence/transition/track composition fixtures; reduced-motion still at `still_time_ms`; golden equality between app and preview within the thresholds in [scene semantics](../07_ANIMATION/SCENE_RENDERER_SEMANTICS.md) §8; anchor-visibility ID-buffer check.

### 18.2 Definition of done (per module)
| Module | Done when |
|---|---|
| Auth/onboarding | Guest → onboarding for all 3 learner-type choices yields the correct start unit (`unit_0` Explorer/undisclosed, `unit_1` New Muslim) and `next_step`, with and without a Goal Anchor; no religion field anywhere; auth sessions revocable; `DELETE /me` purge verified; reviewer lockout works. |
| Journey/sessions | All 4 session kinds serve correct items and feedback modes; all 14 evaluators pass unit tests; finish returns full `SessionResult`; prerequisite access, Soft Lock, Discover identity, track membership and the unit placement skip work; `unlocked` lists newly satisfied lessons. |
| Adaptive engine | Mastery, misconception activation/resolution, FSRS scheduling, term promotion, planner rules covered by unit tests; review sessions select due concepts. |
| Recitation | Correct/missing/substituted/extra/unclear cases pass on a recorded test set (≥ 10 clips; held-out learner audio for acceptance, O-06); ASR runs only in the `asr` worker; capacity `503` path and audio deletion verified. |
| Raqeeb | All 8 classes produce contract-valid messages; guard rules tested; all input types (text, voice, image, DOCX, PDF incl. scanned) processed; untrusted-input and memory-guard tests pass; one answer in progress per conversation; benchmark run stored against P-05 thresholds. |
| Community | XP table, streak, daily goal, leagues (synthetic fill only where P-01 allows it), friends invite/accept with brute-force limits, timezone-change behavior. |
| Duels | Live bot duel end-to-end; friend live duel; disconnect/reconnect with fresh tickets; coordinator takeover; async flow incl. idempotent next/answer and forfeit; scoring and tie rules tested. |
| Scenes | A non-Salah generated lesson whose agent-authored scene passes validation, renders previews with the app renderer, is audited and approved, publishes immutably, and plays in the app with beat/teaching state changes and hotspots — without lesson-specific code or a new app build; fallback and capability gating tested. |
| Factory | Three lessons for three different curriculum slots, with primary types concept, story and practice (at least one of them composing a scenario or practice step inside a different primary type), produced end-to-end through both gates (plans with outcome, prerequisites, arc, reasoning tools, standalone decision and budgets), Arabic variants localized to English, published, and playable in sessions; image audit and religious/factual and pedagogical QA blockers work; at least one generated lesson uses a built-in visual chosen by the Visual Selector; evidence budget, presentation, arc-coverage, role/claim and localization-parity validators block invalid drafts. |
| Pre-generation quality | Every published lesson's supporting scripture evidence carries a semantic review and no unresolved `scholarly_review` blocker; every visual is `compiled` or `audited`; `contextual.placeholder_media_errors` is empty for every lesson version; the unit review shows no unexplained monotony; example, writing, story and exercise-fit model rows run on every draft. |
| Presentation & visuals | Registry validation, storage, publishing, sessions, resume, previews, blind tests, and gold import all preserve `Visual` descriptors, story beats/quotes, teach points/`visual_params`, `objectives`, `completion`, and exercise presentations unchanged. |
| Salah reference | Imported from the generated gold file (fixture ID `les_u1_l3`), passes all validators (a quiz-count warning for its 6 graded exercises is expected), is reachable at curriculum slot 3.2 in Unit 3, and equals the four generated fixtures after ID normalization (§18.1). |
| Learner app data | Activity calendar, quests, achievements, league tiers/promotion, privacy effects, guides, avatars, card and quick reviews, group challenges — each with tests. |
| Coverage | Contract Appendix B is kept current with honest status; nothing is marked verified without passing mock and live checks. |
| Reviewer/metrics | Blind test flow and `/admin/metrics` return real computed values. |
