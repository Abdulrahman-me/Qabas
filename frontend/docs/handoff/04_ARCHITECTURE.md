# 04 — Architecture

Clean Architecture, organised by feature, with BLoC for state, use cases for actions, repositories for data, and get_it for wiring. The goal is that several agents can build different features at the same time without touching each other's files, and that any data source can be swapped (mock ↔ live) without UI changes.

## 1. Layers and the dependency rule

```
   presentation  ──────►  domain  ◄──────  data
 (widgets, BLoCs)     (entities, repo     (DTOs, mappers, data sources,
                       interfaces, use     repository implementations)
                       cases: pure Dart)
            ▲                                   ▲
            └──────────── app/ (DI, router) ─────┘   wires everything together
```

| Layer | May import | Must not import |
|---|---|---|
| `domain/` | Dart core, `equatable`, `meta`, `core/error` (Result, Failure), `shared/domain` | Flutter, Dio, JSON annotations, Rive, `data/`, `presentation/`, other features |
| `data/` | its feature's `domain/`, `shared/domain`, `shared/data`, `core/network`, `core/storage`, `json_annotation` | `presentation/`, Flutter widgets, other features' `data/` |
| `presentation/` | its feature's `domain/` (entities, use cases), `shared/domain`, `shared/presentation`, `core/design_system`, `core/characters`, `core/l10n`, `flutter_bloc` | `data/` (no DTOs, data sources or Dio), other features' internals |
| `app/` | everything (composition root only) | — |

Features never import each other. To share, move the type into `shared/`. To react to another feature, listen on `AppEventBus` (§8). To navigate, use route names from `app/router/routes.dart`.

## 3. Domain layer

**Entities**: immutable, `final class`, `Equatable`, `const` constructors, no `fromJson`. Use domain-friendly names and types (`Duration` instead of `_ms` ints, `DateTime` instead of strings, enums with an `unknown` member). Opaque IDs stay `String` and are never parsed.

**Result and failures** (`core/error/`):

```dart
sealed class Result<T> {
  const Result();
  R fold<R>(R Function(Failure f) err, R Function(T v) ok) => switch (this) {
        Ok<T>(:final value) => ok(value),
        Err<T>(:final failure) => err(failure),
      };
}
final class Ok<T> extends Result<T> { const Ok(this.value); final T value; }
final class Err<T> extends Result<T> { const Err(this.failure); final Failure failure; }

sealed class Failure extends Equatable {
  const Failure();
  @override List<Object?> get props => [];
}
final class NetworkFailure extends Failure { const NetworkFailure(); }           // offline, timeout, DNS
final class UnauthorizedFailure extends Failure { const UnauthorizedFailure(); } // 401 (handled globally too)
final class ForbiddenFailure extends Failure { const ForbiddenFailure(); }
final class NotFoundFailure extends Failure { const NotFoundFailure({this.reason}); final String? reason; }
final class ValidationFailure extends Failure { const ValidationFailure(this.message, {this.field}); final String message; final String? field; }
final class ConflictFailure extends Failure { const ConflictFailure(this.code, {this.details = const {}}); final String code; final Map<String, Object?> details; }
final class RateLimitedFailure extends Failure { const RateLimitedFailure(this.retryAfter); final Duration retryAfter; }
final class PayloadTooLargeFailure extends Failure { const PayloadTooLargeFailure(); }
final class UnsupportedMediaFailure extends Failure { const UnsupportedMediaFailure(); }
final class ClientOutdatedFailure extends Failure { const ClientOutdatedFailure(); }  // 426 (handled globally)
final class UpstreamUnavailableFailure extends Failure { const UpstreamUnavailableFailure({this.retryAfter}); final Duration? retryAfter; }
final class ServerFailure extends Failure { const ServerFailure(); }
final class UnexpectedFailure extends Failure { const UnexpectedFailure(this.debugMessage); final String debugMessage; }
```

(Add `props` overrides where fields exist.) Failures never carry user-facing text except `ValidationFailure.message`, which the contract says to show inline. Presentation maps failures to ARB strings ([12](12_STATES_AND_ERRORS.md)).

**Repository interfaces**: one per feature aggregate, defined in `domain/repositories/`, returning `Future<Result<T>>` (or `Stream<T>` for live data such as the challenge socket).

**Use cases**: one action each, a single `call`, no Flutter. They orchestrate repositories and apply product rules that are not backend-owned (for example "derive the Today card from next step + stats"). Thin pass-through use cases are fine; they keep BLoCs independent of repository shape.

```dart
final class GetJourney {
  const GetJourney(this._repository);
  final JourneyRepository _repository;
  Future<Result<Journey>> call() => _repository.getJourney();
}
```

## 4. Data layer

- **DTOs** mirror the contract exactly (snake_case JSON keys via `@JsonKey(name:)` or `fieldRename: FieldRename.snake`), explicit nullables, enums with `unknownEnumValue`. Details in [06](06_DATA_MODELS.md).
- **Mappers** are pure functions DTO → entity (and entity/draft → request DTO). They're unit-tested with real fixtures.
- **Remote data sources** call `ApiClient` (never raw Dio) and return DTOs or throw `ApiException`.
- **Local data sources** (`core/storage` wrappers) for tokens, preferences and session resume.
- **Repository implementations** combine data sources, map DTOs, cache where useful, and convert exceptions with `guard`:

```dart
Future<Result<T>> guard<T>(Future<T> Function() body) async {
  try {
    return Ok(await body());
  } on ApiException catch (e) {
    return Err(e.toFailure());        // 05 §4: HTTP status + error.code → Failure
  } on FormatException catch (e) {
    return Err(UnexpectedFailure('decode: ${e.message}')); // contract drift: log it, show generic error
  }
}

final class JourneyRepositoryImpl implements JourneyRepository {
  JourneyRepositoryImpl(this._remote);
  final JourneyRemoteDataSource _remote;

  @override
  Future<Result<Journey>> getJourney() => guard(() async => (await _remote.fetchJourney()).toEntity());
}
```

There is **one** remote data source per feature. Mock mode does not swap it: the fake backend answers its HTTP requests ([07](07_MOCKS_AND_BACKEND_SYNC.md)). Only behaviour that has no endpoint at all (local preferences, resume state) uses a `Local…DataSource`. If a feature ever needs a temporary `Mock…Repository` (an endpoint the contract doesn't define yet), register it in that feature's injection file behind the same interface and log it in `docs/API_ASSUMPTIONS.md`.

## 5. Presentation layer and BLoC conventions

**Pages and views.** A *page* provides BLoCs, wires listeners (navigation, sheets, snackbars, companion cues) and picks the view for the state. *Views and widgets* are declarative: they take entities or state slices plus callbacks that add events. They never call use cases, repositories or `sl`.

**One BLoC per screen or flow**, created in the page with `BlocProvider(create: (_) => sl<JourneyBloc>()..add(const JourneyRequested()))`. Use `Cubit` only for small, event-less local state (preferences toggles, a draft text field). Shared app-wide BLoCs are provided above the router (§7).

**Events** are `sealed`, named `<Subject><PastTenseVerb>`: `JourneyRequested`, `JourneyRefreshed`, `NodeTapped`, `AnswerChecked`, `CtaPressed`. **States** are one immutable `Equatable` class per BLoC with an explicit status, plus `copyWith`:

```dart
enum LoadStatus { initial, loading, ready, empty, failure }

final class JourneyState extends Equatable {
  const JourneyState({
    this.status = LoadStatus.initial,
    this.journey,
    this.nextStep,
    this.failure,
    this.refreshing = false,
    this.openPopoverLessonId,
  });
  final LoadStatus status;
  final Journey? journey;
  final NextStep? nextStep;
  final Failure? failure;
  final bool refreshing;           // pull-to-refresh/background refresh keeps the content visible
  final String? openPopoverLessonId;

  JourneyState copyWith({ /* … */ });
  @override
  List<Object?> get props => [status, journey, nextStep, failure, refreshing, openPopoverLessonId];
}
```

Complex flows (the session player, the challenge) use a richer state with a `phase` enum. See [11](11_SESSION_PLAYER.md).

**Handlers** are small, `async`, and pick a concurrency transformer from `bloc_concurrency`: `droppable()` for loads and submits (ignore double taps), `restartable()` for refresh/search, `sequential()` for answer submissions. Every data-fetching BLoC implements loading → ready/empty/failure and a retry event.

```dart
final class JourneyBloc extends Bloc<JourneyEvent, JourneyState> {
  JourneyBloc({required GetJourney getJourney, required GetNextStep getNextStep, required AppEventBus events})
      : _getJourney = getJourney,
        _getNextStep = getNextStep,
        super(const JourneyState()) {
    on<JourneyRequested>(_onRequested, transformer: droppable());
    on<JourneyRefreshed>(_onRefreshed, transformer: restartable());
    on<NodeTapped>((e, emit) => emit(state.copyWith(openPopoverLessonId: e.lessonId)));
    _sub = events.on<SessionCompleted>().listen((_) => add(const JourneyRefreshed()));
  }
  final GetJourney _getJourney;
  final GetNextStep _getNextStep;
  late final StreamSubscription<SessionCompleted> _sub;

  Future<void> _onRequested(JourneyRequested e, Emitter<JourneyState> emit) async {
    emit(state.copyWith(status: LoadStatus.loading));
    final (journey, next) = await (_getJourney(), _getNextStep()).wait;
    switch ((journey, next)) {
      case (Ok(value: final j), Ok(value: final n)):
        emit(state.copyWith(status: j.units.isEmpty ? LoadStatus.empty : LoadStatus.ready, journey: j, nextStep: n));
      case (Err(:final failure), _) || (_, Err(:final failure)):
        emit(state.copyWith(status: LoadStatus.failure, failure: failure));
    }
  }
  // _onRefreshed: same, but keeps current data and sets `refreshing`.

  @override
  Future<void> close() async {
    await _sub.cancel();
    return super.close();
  }
}
```

**One-shot effects** (navigate, open a sheet, play a cue) come from state transitions, read in the page with `BlocListener(listenWhen: …)`. When a transition alone is ambiguous, add a monotonically increasing `effectId` or a nullable `pendingEffect` that the page clears with an event. BLoCs never receive a `BuildContext`, never navigate and never show UI.

**Sound, haptics and companion** are presentation concerns triggered from listeners or widgets (`SensoryService` from DI, `CharacterController` from the widget). BLoCs expose facts ("evaluation correct", "combo reached 3"), not effects.

**Performance:** use `BlocSelector`/`context.select` for hot paths (progress bar, combo counter, timers); keep painters `const` where possible and keep their `shouldRepaint` checks from the prototype.

## 6. Dependency injection (get_it)

`app/di/injector.dart` is the only composition root:

```dart
final sl = GetIt.instance;

Future<void> configureDependencies(AppConfig config) async {
  // core
  sl
    ..registerSingleton<AppConfig>(config)
    ..registerSingleton<AppEventBus>(AppEventBus())
    ..registerSingleton<TokenStore>(SecureTokenStore(const FlutterSecureStorage()))
    ..registerSingleton<PreferencesStore>(await PreferencesStore.open())
    ..registerLazySingleton<SensoryService>(() => SensoryService(sl()))
    ..registerLazySingleton<CharacterRegistry>(CharacterRegistry.bundled)
    ..registerLazySingleton<CharacterAssetCache>(CharacterAssetCache.new)
    ..registerLazySingleton<MockBackend>(() => MockBackend.standard(config))   // only used when not fully live
    ..registerLazySingleton<ApiClient>(() => ApiClient.create(config, tokens: sl(), mock: sl(), events: sl()))
    ..registerLazySingleton<DuelSocketFactory>(() => config.isLive(LiveGroup.challenges)
        ? WebSocketDuelSocketFactory()
        : FakeDuelSocketFactory(sl()));

  // features (each in its own <feature>_injection.dart)
  registerAuth(sl);
  registerOnboarding(sl);
  registerJourney(sl);
  registerSession(sl);
  // … recitation, glossary, review, raqeeb, profile, streak, community, challenges, reader
}
```

Per feature:

```dart
void registerJourney(GetIt sl) {
  sl
    ..registerLazySingleton(() => JourneyRemoteDataSource(sl()))
    ..registerLazySingleton<JourneyRepository>(() => JourneyRepositoryImpl(sl()))
    ..registerFactory(() => GetJourney(sl()))
    ..registerFactory(() => GetNextStep(sl()))
    ..registerFactory(() => GetUnitGuide(sl()))
    ..registerFactory(() => JourneyBloc(getJourney: sl(), getNextStep: sl(), events: sl()));
}
```

Rules: data sources and repositories are lazy singletons; use cases are factories; BLoCs are **factories** (a new instance per page). App-wide BLoCs are singletons created at bootstrap. Never call `sl<…>()` inside widgets other than in `BlocProvider(create:)` on a page. Tests call `sl.reset()` and register fakes.

## 7. App-wide state

| Holder | Kind | Owns |
|---|---|---|
| `AppSessionBloc` (`features/auth`) | Bloc, singleton | Bootstrap status: `unknown → authenticating → needsOnboarding → ready`, plus `sessionEnded` (after `401`) and `outdated` (after `426`). Holds the current `UserProfile`. Listens to `ApiClient` auth events. |
| `LocaleCubit` (`core/l10n`) | Cubit, persisted locally | The UI language (`en`/`ar`). It's set during onboarding page 1 before the profile exists. After that it follows `UserProfile.language`; changes are applied instantly (RTL switch without restart) and pushed with `PATCH /me`. |
| `PreferencesCubit` (`features/profile`) | Cubit, persisted locally | Sound, haptics, reduced motion, discreet reminders, companion enabled. Never sent to the server. |
| `CharacterSettingsCubit` (`core/characters`) | Cubit | Which character plays each role; on/off ([09](09_CHARACTERS_AND_RIVE.md)) |

`app.dart` builds `MaterialApp.router` with `QTheme.light(arabic: locale == 'ar')`, `locale`, `supportedLocales [en, ar]`, `AppLocalizations.localizationsDelegates`, and the text-scale clamp from the prototype.

## 8. Cross-feature communication: `AppEventBus`

A tiny typed broadcast bus in `core/events/` for facts that several features care about. Features publish facts and subscribe to them; nobody imports another feature.

```dart
sealed class AppEvent { const AppEvent(); }
final class SessionCompleted extends AppEvent { const SessionCompleted({required this.sessionId, required this.kind, required this.streakExtended}); … }
final class TermsMastered extends AppEvent { const TermsMastered(this.termIds); final Set<String> termIds; }
final class ProfileChanged extends AppEvent { const ProfileChanged(this.profile); final UserProfile profile; }   // track/language/goal changed
final class XpChanged extends AppEvent { const XpChanged(); }

final class AppEventBus {
  final _controller = StreamController<AppEvent>.broadcast();
  void publish(AppEvent e) => _controller.add(e);
  Stream<T> on<T extends AppEvent>() => _controller.stream.where((e) => e is T).cast<T>();
}
```

Typical subscribers: the journey refreshes on `SessionCompleted` and `ProfileChanged`; profile/stat chips refresh on `XpChanged`; the shared `TermStateStore` applies `TermsMastered` so underlines disappear immediately.

## 9. Navigation (go_router)

`app/router/routes.dart` holds route names and path builders. Each feature exports its `RouteBase`s; `app_router.dart` assembles them. Keep the prototype's structure and transitions.

| Path | Page | Notes |
|---|---|---|
| `/splash` | Splash | initial location |
| `/update-required` | Blocking update | when `AppSessionBloc.outdated` |
| `/welcome` | Onboarding | when `needsOnboarding` |
| `/journey` · `/discover` · `/raqeeb` · `/community` · `/profile` | Shell tabs (`StatefulShellRoute.indexedStack`) | `HomeShell` bottom bar / rail. Discover is tab 1 (there is no Review tab: card review starts from the Journey's Review card, and "Your words" lives in Profile) |
| `/raqeeb/c/:conversationId` | Raqeeb chat | the tab root shows the latest conversation or welcome; the list is `/raqeeb/history` |
| `/lesson/:lessonId/intro` → `/session/:sessionId` | Lesson intro, session player | root navigator, `fadeThrough(fromBottom: true)` |
| `/session/:sessionId/result` | Session result / lesson complete | |
| `/streak` | Streak celebration (from result) or calendar (from profile) | `?celebrate=1` |
| `/review/session/:sessionId` | Card review (from the Journey's Review card) | |
| `/glossary` · `/achievements` · `/settings` · `/about` · `/reader/:lessonId` | root navigator | |
| `/challenge/new` · `/challenge/:duelId` · `/challenge/:duelId/result` | Challenges | |
| `/reviewer/...` | Reviewer console (Tier C) | renamed from the handoff's `/review/*` so it can't clash with the learner's `/review/session` route |

**Guards:** `redirect` reads `AppSessionBloc.state` through a `GoRouterRefreshStream` adapter: `outdated` → `/update-required`; `unknown/authenticating` → `/splash`; `needsOnboarding` → `/welcome`; `ready` + `/welcome` → `/journey`. Never loop on `401` ([05](05_NETWORKING_AND_API.md) §5).

**Passing data:** pass IDs in the path, not objects in `extra` (extras are lost on restoration). The result page reloads the stored `SessionResult` by calling the idempotent finish again or reading the repository cache. `extra` is allowed only for purely visual hints (for example "play the celebration").

## 10. Testing layout

- `test/features/<f>/domain/`: use cases with fake repositories.
- `test/features/<f>/data/`: mappers and repositories decoding **real fixtures** from `assets/mocks/`.
- `test/features/<f>/presentation/`: `bloc_test` for every event path, including failure and retry; widget tests for key views with `MockBloc` (`mocktail`/`bloc_test`).
- `test/contract/`: decodes every vendored contract fixture and API example through the DTOs ([07](07_MOCKS_AND_BACKEND_SYNC.md) §6).
- `integration_test/tour_test.dart`: the ported prototype tour in mock mode (fidelity screenshots).
