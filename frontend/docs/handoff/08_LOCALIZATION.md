# 08 — Localization

**Never hard-code a user-facing string.** Every visible string comes from ARB: titles, buttons, navigation labels, errors, loading and empty messages, tooltips, dialog text, semantics labels, character text, AI stage and status messages, form labels and validation messages. Content (lessons, answers, Raqeeb, quest titles, league tier names, achievement titles) arrives from the API already localised and is rendered verbatim.

The app ships **English and Arabic** from day one (English is the template). The prototype already has every interface string in both languages (`/Users/aw/Documents/qpr/qabas/lib/l10n/*.dart`, about 280 `t('en','ar')` pairs), so this is extraction, not translation. A further language later means adding ARB files only.

## 1. Setup

`pubspec.yaml`: `flutter_localizations` (sdk), `intl`, and `flutter: generate: true`.

`l10n.yaml`:

```yaml
arb-dir: lib/l10n/arb
template-arb-file: app_en.arb
output-dir: lib/l10n/gen
output-localization-file: app_localizations.dart
output-class: AppLocalizations
nullable-getter: false
untranslated-messages-file: build/untranslated.json
```

Access with an extension in `core/l10n/l10n_x.dart`:

```dart
extension L10nX on BuildContext {
  AppLocalizations get l10n => AppLocalizations.of(this);
  bool get isArabic => Localizations.localeOf(this).languageCode == 'ar';
}
```

`MaterialApp.router`: `localizationsDelegates: AppLocalizations.localizationsDelegates`, `supportedLocales: AppLocalizations.supportedLocales`, `locale:` from `LocaleCubit`.

## 2. Per-feature fragments (no merge conflicts between agents)

`flutter gen-l10n` needs one ARB file per locale, which would be a merge-conflict hotspot when several agents work in parallel. So each feature owns fragments that a small tool merges:

```
lib/l10n/fragments/common_en.arb      common_ar.arb        # Phase 1: buttons, errors, units, plurals
lib/l10n/fragments/journey_en.arb     journey_ar.arb       # journey agent only
lib/l10n/fragments/session_en.arb     session_ar.arb
…
lib/l10n/arb/app_en.arb  app_ar.arb                        # GENERATED by tool/merge_arb.dart; never edit by hand
```

`tool/merge_arb.dart` (write it in Phase 1) merges the fragments per locale, sorted by key, with `@@locale`. It **fails** on a duplicate key, a key missing in either locale, or mismatched placeholders between locales. Run `dart run tool/merge_arb.dart && flutter gen-l10n` after editing any fragment. Commit the generated `arb/` files so the app builds without the tool.

## 3. Key naming

`lowerCamelCase`, prefixed by the owning feature: `journeyStartLesson`, `sessionCheck`, `raqeebStageVerifying`, `profileDeleteAccountTitle`. Shared words live in `common`: `commonContinue`, `commonCheck`, `commonClose`, `commonRetry`, `commonCancel`. Errors are `error<Kind>Title` / `error<Kind>Body`. Semantics labels end in `Semantics` (`characterGuideSemantics`). Tooltips end in `Tooltip`.

Every key has an `@key` description for translators, saying where it appears and its tone.

```json
"sessionFeedbackNotQuite": "Not quite",
"@sessionFeedbackNotQuite": { "description": "Title of the feedback panel after a wrong answer. Warm, never scolding." },
```

Variant lists in the prototype (praise and gentle titles in `strings_learn.dart`, review intervals in `strings_app.dart`) become numbered keys (`sessionPraise1…sessionPraiseN`). The BLoC picks an index deterministically (for example the exercise id hash), and the widget maps the index to the key.

## 4. Numbers, plurals, dates

**Digits.** Arabic UI shows Arabic-Indic digits (٠١٢٣…) and the Arabic decimal separator (٫), as the prototype's `S.n()` does. Don't rely on `intl` locale defaults for this. Port `S.n` to `core/l10n/q_numbers.dart` (`QNumbers.format(num, locale)`) with a unit test, and pass **pre-formatted strings** into ARB placeholders:

```json
"journeyEmbersCount": "{count} embers",
"@journeyEmbersCount": { "placeholders": { "count": { "type": "String" } } }
```

**Plurals** need a numeric selector, so pass both the number (for the plural category) and the formatted text (for display). Arabic has six categories (`zero`, `one`, `two`, `few` 3–10, `many` 11–99, `other`), and the prototype's streak wording follows them:

```json
"streakDayCount": "{count, plural, =1{{countText} day streak} other{{countText} day streak}}",
"@streakDayCount": { "placeholders": { "count": { "type": "num" }, "countText": { "type": "String" } } }
```
The Arabic entry reproduces the prototype's `S.dayStreak` forms exactly (1 → يوم, 2 → يومان, 3–10 → أيام, 11+ → يومًا, followed by متتالية):

```json
"streakDayCount": "{count, plural, =1{{countText} يوم متتالية} =2{{countText} يومان متتالية} few{{countText} أيام متتالية} many{{countText} يومًا متتالية} other{{countText} يومًا متتالية}}"
```

Port every Arabic plural from the prototype's own logic (`S.dayStreak`, `S.days`, `S.minutesLong`, `cardsReady`) case by case. Don't write new Arabic grammar; ask the owner when the prototype has no form for a case.

**Dates and times**: `DateFormat` with the current locale (`intl`), weekday names on the streak week, and relative times for Raqeeb conversations ("2 h ago") from ARB patterns. Everything is computed in the learner's local time zone from server UTC timestamps.

## 5. Right-to-left rules

- Directionality follows the locale automatically. Use `EdgeInsetsDirectional`, `AlignmentDirectional`, `PositionedDirectional`, `BorderRadiusDirectional` and `start`/`end`, never `left`/`right`, in layout code.
- Switching language in Settings updates the UI **instantly** without a restart (`LocaleCubit` → `MaterialApp.locale` and `QTheme.light(arabic:)`).
- `ProgressTrack` fills from the reading start (flipped in RTL), as in the prototype.
- **Scenes, maps, pins and illustrations are not mirrored** in RTL. Only the surrounding UI follows reading direction. The exception is `pillars`: in Arabic the renderer is flipped (as `TeachView` does), so each pillar stays above its localised label in reading order.
- **Quran text is always RTL**, even inside the English UI (`Directionality(textDirection: TextDirection.rtl)` around `QuranText`). The same applies to Arabic hadith text, canonical Arabic term displays, and Arabic secondary labels in English ordering tokens.
- Typography switches by locale in the theme (Figtree ↔ IBM Plex Sans Arabic, with taller Arabic line heights). Never set font families in feature code.
- Button labels are uppercased only in Latin scripts (`QButton` handles it).
