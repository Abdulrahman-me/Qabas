# API assumptions and integration status (Qabas app)

The living record of every place where the Flutter client relies on something the contract (`docs/contract/03_API/API_REQUIREMENTS.md`, amended revision 10, schema digest `9d67bda0…481c`) doesn't state exactly, or where the client deliberately differs from the prototype. Share it with the backend engineer. Each open item should be confirmed, corrected or closed.

Rules:
- Every assumption has an ID (`A-xx`). The code that depends on it carries `// TODO(contract): A-xx` and lives in `data/` (DTOs, mappers, data sources) unless it's a pure UI decision.
- Never edit an old entry's meaning. Close it and add a new ID if the decision changes.
- Status values: `open` (unconfirmed), `confirmed` (agreed with backend/owner, with a date), `changed` (superseded by `A-yy`), `closed` (no longer relevant).
